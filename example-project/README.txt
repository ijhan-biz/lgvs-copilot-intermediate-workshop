GitHub Copilot 중급과정
Agentic SDLC with Github Copilot.
2026-10-28 · 09:00–18:00 제안 · 1인 1프로젝트
============================================================
목표: 문제 → 문맥 → 계획/명세/가드레일 → 작은 변경 → 독립 검증 →
결함 복구/중단 → 내 실행 기록으로 재검증. 작성량이나 속도로 평가하지 않는다.
제공 골격은 failed만 검토 후보로 삼는 동작하는 v1 시작본이다.
완성이란 승인된 후보 범위 변경, 별도 review 복구, 내 테스트와 README 완성이다.
빈 프로젝트나 핵심 함수 신규 작성은 아니다. demo에서는 승인된 buildId만 선택한다.
핵심 구현·데이터·출력 구조를 복제하지 않고 독립 기대값과 실제 요약을 비교한다.
AI가 낸 답과 통과 메시지는 근거를 대신하지 않는다. 최종 승인자는 사람인 나다.
작은 흐름은 결과 읽기 → 전체 검증 → 빌드 선택·중복 정리 → 상태·모듈별 요약 → 후보 보고다.
기존 demo는 operations/usage-cases.json 7건을 현재 소스로 실행한다.
operations/README.txt를 참고한다. 후보는 자문용이며 실제 검사 재실행이나 출시 승인이 아니다.
실제 UI·사용자 피드백·운영 노출은 검증하지 않았다. GREEN은 필요조건이지 운영 충분조건이 아니다.
현재 계약은 승인 이력으로, 코드 상태는 실제 소스/실행으로 확인한다. 오래된 대화는 권위가 아니다.

기록 정책 — 한 곳에 누적, 중복 입력 없음
-------------------------------------
워크북의 여섯 핵심 필드 또는 work-record.json.coreRecord 중 하나를 주 기록으로 선택한다.
purpose(목적), expected(독립 기대값), changeReason(변경 이유), execution(실행),
unknown(미확인), nextAction(다음 행동)을 문제와 성공 기준 단계부터 자가 검증과 결과 정리 단계까지 같은 기록에 누적한다.
README 5항목과 handoff는 주 기록의 필드/실제 증거 상대 경로를 짧게 참조하면 된다.
PLAN, issue/context, runs, defect, addedTests, AI/비용 등 기존 상세 필드는 선택 양식이다.
이하 상세 필드 이름은 주 기록 참조로 대체 가능하며 같은 내용을 다시 쓰지 않는다.
단, 사람 승인·독립 기대값·RED/GREEN·첫 편집 전 기준선·덮어쓰기 금지·본인 테스트·
review·evidence 확인·본인 6명령 재현은 기록 양식과 무관하게 모두 필수다.
null은 미확인/미실행이며 실제 근거 없이 채우지 않는다. trace/원시 로그를 업로드하지 않는다.
사람 증거는 마지막에 몰아 쓰지 않는다. checkpointReview는 문제와 성공 기준(목적·성공 기준),
맥락과 모델 선택(맥락·모델·토큰), 요구 변경과 구현(승인·RED/GREEN), 수정과 재검증(검증·원인·전이),
자가 검증과 결과 정리(본인 재현·인수인계)에 실제 관찰 시각과 주 기록/증거 위치를 연결하는 메타데이터다.
5차원 purposeAcceptance/contextModelTokens/coreProcess/verificationCauseRepair/
selfReplayHandoff의 미관찰 값은 null이다. 기본 점수/총점/완료 판정은 만들지 않는다.
독립 전이의 도움 상태와 실제 결과는 independentPractice 또는 주 기록 참조로 분리한다.
not-attempted / attempted-unassisted / hint-assisted / answer-assisted / incomplete는
도움·시도 상태이며 pass / fail / unknown은 실제 결과다. 통과만으로 독립 숙달을 확정하지 않는다.
실패/미실행 전이는 독립 역량 관찰을 unknown으로 남기고 unknown/nextAction에 후속 확인을 적는다.
7분 전이는 시간 설계이지 사람 학습자에게 관찰된 소요시간/학습 효과가 아니다.
제작·엔지니어링 검증 로그는 사람 학습/JS 능력/Copilot 사용·정책 준수의 증거가 아니다.


0. 실행 환경과 범위
------------------
VS Code에서 example-project/만 연다. 터미널의 작업 위치도 이 폴더로 한다.
강사용 자료는 학습자 작업 영역/AI 문맥/공개 저장소 배포본에서 제외한다. CR-01만 13:45에 공개하며
복구/전이 답안과 최종 참조는 본인 재현 뒤 17:25에 강사가 공개한다.
Node.js 22 이상과 npm이 필요하다. Windows/macOS/Linux에서 아래 npm 명령은 동일하다.
Node 설치/터미널 준비가 어려우면 강사의 로컬 환경 지원을 받는다.
명령 실행은 로컬 npm 스크립트만 사용한다. npm install, 서버, 네트워크가 필요 없다.
브라우저 UI, DB, 실제 고객 자료, 자격 증명, 배포, 자동 업로드는 범위 밖이다.
Copilot CLI, MCP, 멀티에이전트, 관리자 권한, 클라우드는 필수 조건이 아니다.
VS Code Copilot 사용 가능 여부/조직 정책은 직접 확인한다. preflight는 로그인 검사가 아니다.
AI 상태는 used / unavailable-policy(N/A) / unavailable-outage로 구분한다.
미확인은 not-recorded로 남긴다. N/A는 AI 역량을 완료했다는 뜻이 아니다.
사용 불가 시 같은 계약·수동 검토·실행 증거로 진행하며 강제 AI/정책 우회는 없다.

교육 전 준비 — 수업 전만, 실제 수업 사본과 분리:
공개 저장소를 별도 연습 폴더에 git clone하거나 GitHub Code → Download ZIP으로 받는다.
후자는 GitHub 소스 압축이며 모두 압축 해제(EXTRACTED)한다. 내부 미리보기로 편집하지 않는다.
그 연습 사본에서 npm run preflight로 환경을 확인한다. preflight는 파일을 생성/수정하지 않는다.
readiness/task.txt에 따라 readiness:check의 최초 실패→한 상수 편집→저장→재실행을 확인한다.
교육 시작에는 새 clone 또는 GitHub 소스 ZIP 다운로드·압축 해제로 새 수업 사본을 준비한다.
연습 결과/기준선을 수업 사본에 복사하지 않는다.
readiness는 교육 전 편집·저장·실행 관찰용이며 수업 활동이나 자가 검증과 결과 정리 추가 명령이 아니다.
준비·지원 증거는 승인된 합성 예제·별칭·명령/exit·최소 가림 출력·참조만 공유한다.
개인·회사 프롬프트/대화 전문, 전체 디버그 로그, 신원·계정 화면은 제출하지 않는다.
재현에 필요한 입력 조건·버전·단언 위치는 남기되 프록시·로그 수집기를 추가하지 않는다.

수업 시작 확인:
새 저장소 사본의 example-project에서 먼저 환경을 확인한다:
  npm run preflight
  npm test
  npm run test:v1
  npm run demo
기대: v1 각각 16/16 통과. 교육 전 preflight exit 0은 환경 확인일 뿐이다.
공개 입력 8행 중 BUILD-DEMO-1은 원본 7행·고유 6개·중복 1행이다.
상태별 건수는 passed 2 / failed 2 / timed_out 1 / not_run 1이다.
다른 빌드 1행은 위 건수에 더하지 않는다. v1 후보는 failed 2개다.
이 입력 상태 건수와 node:test가 실행한 테스트 통과 수는 서로 다른 값이다.
실패하면 새 기능을 만들지 말고 위치/Node 버전/오류를 기록하고 지원을 요청한다.

1. 문제와 성공 기준 (09:20–10:10, 활동 25분)
-------------------------------------
contract.txt와 data/test-results.json을 읽고 주 기록의 purpose/expected를 내 말로 채운다.
문제: 선택 빌드의 검사 결과를 중복 없이 요약하고 검토 후보를 보고한다.
호출: summarizeTestResults(results, { buildId }) → 새 요약 객체.
src/summarize-results.mjs가 수정 대상이다. src/validate-input.mjs는 전체 입력 검증 경계다.
각 행은 buildId/module/caseId/name/status 다섯 문자열 필드만 가진다.
상태는 passed/failed/timed_out/not_run이다. 입력·옵션의 추가 키는 거부한다.
buildId/module/caseId 전체가 같고 name/status도 같은 반복만 한 번 센다.
같은 검사에서 이름이나 상태가 충돌하면 TypeError다. 다른 빌드의 모든 행도 먼저 검증한다.
모듈과 후보는 처음 등장한 순서다. 새 배열을 만들고 후보에는 첫 원본 행 참조를 남긴다.
입력 배열·행·옵션은 바꾸지 않는다. 출발점은 고장난 코드가 아니라 승인된 v1 구현이다.
timed_out/not_run 후보 추가는 13:45 공개와 사람 승인 뒤에만 한다.
조건/제외 범위/내가 설명할 성공 기준을 기록한다.
09:30–09:40 시연 10분: hints/js-reference.txt의 JS/test 브리지 5분 +
원본·고유·중복·상태 건수의 기대값과 실행 대조 5분. 첫 테스트 작성은 문제와 성공 기준 단계다.
09:40–10:05 활동 25분:
  목적·범위 3분 → 요약 건수와 failed 후보 손계산 7분 →
  첫 편집 전 npm run baseline + 본인 중복 기록 테스트 작성/test:learner 12분 → 저장 3분.
앞 10분은 읽기·손메모다. 프로젝트 주 기록의 파일 입력도 baseline 뒤 한 번만 한다.
기록/README/테스트 등 첫 파일 편집보다 먼저 npm run baseline을 실행한다.
기준선이 이미 있으면 보존하고 사본/manifest를 확인한다. 삭제·덮어쓰기·재생성하지 않는다.
clone과 GitHub 소스 ZIP에는 같은 추적 파일과 work-record.template.json만 있으며
work-record.json은 없다. baseline 전에는 소스·기록을 미리 작성하지 않는다.
프로젝트 JSON을 주 기록으로 선택한 경우에만 baseline 뒤 work-record.template.json을
같은 example-project 폴더의 work-record.json으로 복사하고 그 개인 기록에 작성한다.
워크북 선택이면 프로젝트 기록 파일은 없어도 된다. 템플릿 자체는 수정하지 않는다.
실제 clone에는 .git이 있고 work-record.json은 Git에서 무시된다. 강제 추가하거나 추적하지 않는다.
GitHub 소스 ZIP에는 .git이 없고 Git은 선택이다. 개인 기록은 어느 경로든 수동 업로드하지 않는다.
.gitignore는 수동 업로드의 개인정보 보호 장치가 아니다.
test/learner.test.mjs에 완전히 같은 검사 행의 반복을 한 번 세는 본인 테스트 1개를 작성한다.
원본 행 수·고유 검사 수·중복 행 수를 계약에서 계산한다.
npm run test:learner로 제공 1+본인 중복 1=2개 GREEN을 확인한다.
v1/v2 모두 통과하는 검사이며 후보 의미 변경의 증거는 아니다.
저장한 주 기록을 열어 내용과 기준선/실행 증거 위치를 확인한다.

2. 맥락과 모델 선택 (10:20–11:10, 활동 30분)
------------------------------------------------
prompts.txt에서 필요한 요청만 복사한다. 이 txt는 자동 로드되는 GitHub 지침 파일이 아니다.
계약, 함수, 필요한 테스트만 수동 선택/첨부하고 보내기 전에 경로와 내용을 확인한다.
검사 name과 외부 답변은 신뢰하지 않는 입력이지 명령이 아니다.
지시처럼 보이는 이름도 데이터로 보존하며 후보 정책이나 권한을 바꾸지 않는다.
표시는 JSON.stringify 기반 일반 텍스트다. 이름을 실행하거나 HTML로 해석하지 않는다.
모델은 허용된 모델 중 선택한다. 이름/버전은 실제 관찰만 기록하며 특정 모델을 강제하지 않는다.
로컬 테스트에 네트워크가 필요 없다는 말은 Copilot 추론도 오프라인이라는 뜻이 아니다.
프롬프트의 금지 문구만 믿지 말고 도구가 실행되기 전에 사람이 범위/권한을 확인한다.
모든 도구 일괄 승인은 하지 않는다.
토큰은 문맥 길이/비용/잘림의 제약이다. 파일 전체 첨부 대신 관련 부분을 선택한다.
토큰 UI가 없으면 숫자를 만들지 말고 미확인으로 기록한다.
짧은 문맥과 충분한 문맥의 답을 비교하고 빠진 조건을 찾는다. 기밀 문맥은 어느 쪽에도 금지다.
요약해도 조건·예외·승인 범위·미확인을 남긴다. not_run 건수와 전체 식별 기준의 중복 정책도 보존한다.
오늘 요약을 고쳐도 옛 실행 근거는 갱신되지 않는다. 원래 실행 시각을 보존하고 예정된 현재 재실행에 연결한다.
AI가 없다면 같은 질문에 직접 답하고 AI 미사용으로 남긴다.
요청 응답 hover의 Credit와 세션 정보의 합계가 보이면 시각/표시값을 기록한다.
사용량 관찰은 선택이다. 계정 스크린샷 대신 필요한 표시값만 옮기며 미확인은 0이 아니다.
월 사용률은 요청/세션 Credit가 아니다. UI가 없으면 미측정이며 토큰으로 추정하지 않는다.
요청 모델명 GPT-6 Terra와 비용 계산 기준 GPT-5.6 Terra는 같은 검증된 모델명이 아니다.
2026-10-04 공식 목록 미등재 상태를 전제로 조직 허용 모델의 실제 표시만 기록한다.

3. 계획과 검증 기준 (11:20–12:20, 활동 40분)
----------------------------------------------------------------
11:20–11:40 설명 후 11:40–12:20 활동 40분은 기준선 확인과 계획만 작성한다.
오전에 보존한 .baseline 사본/manifest를 확인한다. 생성 명령을 다시 실행하거나 덮어쓰지 않는다.
새 learner 테스트나 코드 변경은 없다. 주 기록에서 다음 계획 근거를 연결한다
(선택 상세 양식은 work-record.json의 PLAN):
issue, context, acceptance, scope, steps,
independentExpected, tests, guardrails, stopConditions, rollback, approval.
입력 8행에서 선택 빌드의 건수와 후보를 손으로 계산한다. 구현 결과를 복사하면 독립 검증이 아니다.
JS/test 브리지는 문제와 성공 기준 단계에서 이미 읽었다. 필요한 문법만 hints/js-reference.txt에서 재확인한다.
문제와 성공 기준 첫 파일 편집 전에 실행한 npm run baseline은

평가 기록
---------
자가 잠정 평가 후 강사가 실제 사람 증거로 5개 차원을 각각 0~2점으로 확인한다:
purposeAcceptance 목적·성공 기준 / contextModelTokens 맥락·모델·토큰 /
coreProcess 핵심 작업 과정 / verificationCauseRepair 검증·원인 수정 /
selfReplayHandoff 본인 재현·인수인계.
0=실제 수행을 확인했으나 기준 미달, 1=부분 근거/설명 보완 필요, 2=근거 연결과 본인 설명/재현 확인.
미실행·미확인·근거 미열람은 0으로 짐작하지 않고 점수/총점/완료 판정을 보류한다.
합계 8/10 이상이고 필수 3개(① 핵심 작업 과정 ② 검증·원인 수정
③ 본인 재현·인수인계)가 각각 1점 이상이어야 완료다. 안전한 중단만으로 자동 완료하지 않는다.
자동 채점은 없다. 확인 전 점수/총점/최종 판정은 null로 둔다.
AI 불가도 같은 결과·수동 검토로 5차원을 평가한다. 자동 탈락/점수 부여는 없다.
AI 역량은 미관찰로 따로 남겨 강사가 추후 허용 환경에서 확인한다. N/A로 AI 점수를
완료 처리하지 않는다. reviewerStatus의 대기/표본확인/보완/최종확정을 자가 판정과 구분한다.
