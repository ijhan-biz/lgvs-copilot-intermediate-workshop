내 실행 안내 — 짧은 기록 위치와 재현 명령
=======================================
빈 양식은 실행 증거가 아니다. 아래에는 주 기록 필드와 실제 증거의 상대 경로만 연결한다.
워크북 여섯 핵심 필드 또는 work-record.json.coreRecord 한 곳을 선택해 누적한다.
PLAN/runs/defect/AI/비용 등 상세 양식은 선택이며 이 문서에 내용을 다시 입력하지 않는다.

주 기록 파일/필드 위치:
  purpose / expected:
  changeReason:
  execution / 실제 증거 상대 경로:
  unknown / nextAction (AI/도움 상태와 미확인·다음 확인 포함):
README 끝 5항목 참조 / 기록 고정 시각 / 저장 파일 열기 확인 위치:
새 비판·채택/기각 / 본인 재현 / 강사 비교 / 잠정 평가 근거 위치:
현재 단계·승인 버전/범위·시각·결정 이력 / 폐기된 가정의 주 기록 위치:
현재 소스·계약·테스트 상대 경로와 확인한 파일 상태 / 실제 실행 수·미실행 옛 주장 위치:
다음 일관된 작업 경계·담당자 / 미확인·다음 확인 위치:
선택 probe 해시는 읽은 파일 식별값일 뿐 승인·불변 증명이 아니다. 옛 GREEN을 새 실행으로 쓰지 않는다.
짧게 써도 조건·예외·권한·미확인을 보존한다. not_run 건수와 중복 정책도 빠뜨리지 않는다.
오늘 요약 편집으로 옛 증거가 갱신되지는 않는다. 원래 실행 시각/근거와 아래 현재 재실행을 연결한다.
비판의 기각 이유·재검토 조건은 기존 changeReason을 참조한다. 현재 요구의 판단을 영구 금지로 바꾸지 않는다.
값이 비어 있으면 NOTEXECUTED/미확인이다. 단계 선언은 승인 근거를 대신하지 않는다.

재현 전제: Node >=22, example-project 폴더, 승인된 C2-v2와 유지한 C1,C3~C6.
호출은 summarizeTestResults(results, { buildId })다. src/summarize-results.mjs와
data/test-results.json, review/summarize-results.mjs를 구분한다.
review는 이미 생성/수정했으면 다시 생성하지 않는다. 처음 준비할 때만 prepare:review를 쓴다.
기존 .baseline/review는 삭제·초기화·덮어쓰기 금지다. 실패/누락은 보존하고 지원 요청한다.

본인 6명령 — 새 터미널에서 이 문서만 보고 실제 재실행
  npm run preflight
  npm run test:v2
  npm run test:learner
  npm run test:review
  npm run demo
  npm run evidence
기대: v2/review 각각16 GREEN, learner4 GREEN이다. 실제 수·exit는 본인이 확인한다.
공개 입력 8행 중 선택 BUILD-DEMO-1은 원본7/고유6/중복1이다.
상태는 passed2/failed2/timed_out1/not_run1이며 다른 빌드1행은 합산하지 않는다.
v1 후보2개, 승인된 v2 후보4개다. 상태·모듈별 건수와 처음 등장 순서는 유지한다.
입력 상태 건수는 node:test 통과 수와 다르다. 후보는 자문이며 실제 재실행·출시 승인이 아니다.
demo는 같은 명령 안에서 합성 사용 사례 7건의 요약·후보·오류·다음 질문도 표시한다.
단계 미기록(not-recorded)과 실제 후보 관찰을 승인 기록과 대조한다. 별도 필수 명령은 없다.
빌드 없음의 0건 요약은 유효하다. TypeError는 입력 거부이며 실제 UX 검증은 아니다.
GREEN 이후에도 권한/부하/관측/운영 복구는 미검증이다. 파일럿 질문은 unknown/nextAction에 참조한다.
승인된 buildId 변경 시 해당 요약·후보의 독립 기대값을 주 기록.expected에 연결한다.
learner: 제공1 + 본인 정확한 반복 기록1 + 승인 후 후보 확장1 + C6 원본 보존1 = 4.
첫 본인 테스트는 v1/v2 모두 통과한다. 두 번째는 timed_out/not_run 포함을 v1 RED→v2 GREEN으로 확인한다.
세 번째는 입력 비변경·새 요약과 후보 배열·첫 원본 행 참조를 확인한다.
오전 테스트 재실행은 중복 추가가 아니다. 선택 추가 테스트는 실제 수·이유를 참조한다.

필수 실행 근거 — 주 기록 참조로 충족하되 게이트는 생략하지 않음
  첫 편집 전 문제와 성공 기준 baseline의 시각/exit/manifest와 허용 목록의 사본, 계획과 검증 기준 확인·덮어쓰기 없음.
  compare:baseline은 해시 요약만이다. VS Code의 같은 상대 경로 사본/현재 행 비교로 범위를 확인한다.
  13:45 CR-01 사람 승인 시각·범위, 독립 기대값, 후보 확장 테스트 v1 RED→v2 GREEN.
  문제와 성공 기준 중복2 GREEN / 요구 변경과 구현 후보3 RED→GREEN / 결과와 기준 검증 C6 포함4 GREEN.
  문법·import 오류와 계약 단언의 예상 실패를 구분한다. 오류 이름만으로 의도된 RED라 하지 않는다.
  review 첫 실제 실행 수/exit/실패 단언과 본인 최소 반례를 구분하고 승인 복구 후16 GREEN을 확인한다.
  여러 실패를 여러 결함으로 단정하지 않는다. source validator/공유16/계약은 약화/삭제하지 않는다.
  data/transfer-results.json을 읽고 module/caseId 후보 예측을 expected에 저장한다.
  independent-task.txt에 따라 transfer 테스트를 작성·고정한 뒤 test:transfer를 실행한다.
  예측·이유·expectedIds와 최초 명령의 실제 outcome/exit/출력을 모두 저장·동결할 때까지
  AI·힌트·강사 도움·답안·고급 모델을 닫는다. 미실행은 outcome unknown·exit null로
  동결하고 incomplete/HOLD 뒤 과정 도움을 연다. 무지원 독립 통과로 부르지 않는다.
  transfer 1개는 learner4/공통16과 별개이며 위 6명령에 추가하지 않는다.
  전이 도움 상태(not-attempted/attempted-unassisted/hint-assisted/answer-assisted/incomplete)와
  실제 결과(pass/fail/unknown)를 분리한다. 확인한 fail은 그대로 보존하며 미확인 역량은 후속 확인.
  두 동결 전후 답안/고급 모델 노출은 answer-assisted이며 시점을 남긴다. 구체적 정답은
  17:25 이후 본인6명령 재현·도움 공개 뒤 비교한다. 모델 비교는 수업 종료 후 후속선택연습이다.
  문제와 성공 기준/맥락과 모델 선택/요구 변경과 구현/수정과 재검증/자가 검증과 결과 정리 checkpointReview에 사람 시각·근거를 참조하고 미확인 차원/점수는 null이다.
  새 비판과 채택/기각·재확인, 고정 시각, 각 명령 실제 시각/exit/수/ID/오류.
  AI used / unavailable-policy(N/A) / unavailable-outage / not-recorded를 구분한다.
  AI 불가 시 같은 질문의 수동 비판을 참조하고 실행한 AI 검토라고 꾸미지 않는다.
  강사 답 공개 전 독립 시도 보존, 비교/도움 사용/독립 재시도 과제, 실패·중단·미확인.

evidence/v2-*.json은 실제 파일을 열어 다음을 확인하고 주 기록.execution에 연결한다:
  counts tests/passed/failed/skipped/todo/cancelled, testExitCode/collectorExitCode,
  시작·종료 시각/status/이유, 허용목록·실행도구 SHA-256 전후 동일 여부.
  passed는 testExitCode=collectorExitCode=0, tests=passed=16, 나머지0, 전후 해시 동일일 때만.
  failed/incomplete/state-changed는 collector nonzero다. 실행 중 편집하지 않는다.
  서명된 위변조 방지 증명이 아니며 learner/review/승인/AI 사용까지 증명하지 않는다.
  환경변수/비밀/계정/개인 절대 경로/원시 로그/trace를 넣거나 업로드하지 않는다.
  제출·지원에는 승인된 합성 예제·별칭·명령/exit·최소 가림 출력·참조만 쓴다.
  재현 조건·버전·단언 위치는 보존하되 개인·회사 프롬프트/대화 전문·전체 디버그 로그·신원/계정 화면은 제출하지 않는다.
