참가자 시작 — 업무 변경과 필수 하네스 구축
========================================
상위 폴더 PARTICIPANT-START.txt와 따라하기.html이 전체 시작 경로다.
이 example-project만 VS Code로 열고 Node.js 22 이상에서 preflight와 npm test를 확인한다.
업무 v1 검사 16개 통과는 기대 상태다. 어떤 파일도 편집하기 전에 문제와 성공 기준 단계의 npm run baseline과
실제 .baseline·manifest를 확인한다. 기존 기준선을 덮어쓰지 않는다.

README.txt의 ‘현재 필수 범위’를 읽는다. 단계별 명령과 순서는 상위 폴더 따라하기.html을 따른다.
요구사항 정제 09:20–10:10은 HVE 프레이밍 10분(09:20–09:30) + JS 브리지 10분(09:30–09:40) +
기존 실습 25분(09:40–10:05) + 디브리프 5분(10:05–10:10)이다.
필수 HVE 40분에는 기존 실습 25분이 포함된다. 별도 과정·시간·양식은 추가하지 않는다.
instructions는 맥락 선택 10분에, workflow/run은 오후 구축 25분에 본인이 작성한다.
계획·검증 단계 40분에는 오전 baseline 뒤 handoff.txt [계획]에 세 줄만 쓴다. 런타임·테스트·설정 편집/실행은 금지다.
13:25–13:40은 이미 사람이 검토한 하네스 범위의 workflow 구축만 한다.
업무 후보 정책 변경은 13:45 요청 공개와 실제 사람 승인 모두를 갖춘 뒤에만 한다.
제공된 보호 부품을 쓰되 순서·기록·실패 중단 분기는 직접 만든다. 시작본 check 실패는 예상이다.

프로젝트의 필수 명령:
  npm run harness:check
  npm run harness:approve -- --reason "직접 검토한 범위와 이유"
  npm run harness:run
  npm run harness:drill -- timeout
  npm run harness:drill -- forbidden
  npm run harness:status
  npm run harness:resume -- --latest
이유는 검토한 현재 범위를 자기 말로 쓴다. 로컬 선언은 신원 인증·기업 승인과 다르다.
로컬 하네스 검토 선언은 업무 정책 승인과 별개이며 반드시 하네스 실행보다 먼저 남긴다.
실제 timeout 실패·금지 실행 전 거절은 nonzero가 예상되며 실패 기록을 보존한다.
15:30–15:40 운영 10분 안에 C6 개인 검사 편집을 포함한 현재 파일을 사람이 직접 재검토한다.
npm run harness:approve -- --reason "직접 읽은 현재 파일의 범위와 이유"
→ npm run harness:run → npm run harness:status 뒤 timeout/forbidden을 실행한다.
옛 승인은 APPROVAL_REQUIRED로 거절되며 이 갱신은 13:45 업무 승인과 별개인 로컬 재검토다.
성공 후 허용 instructions 수정으로 stale/재개 거절을 관찰하고 재검토·새 승인·새 실행한다.
동일 fingerprint 중단 작업만 checkpoint에서 이어 가며 재시도 상한·성공 단계 중복 방지를 확인한다.
달라진 fingerprint는 강제 재개하지 않는다. 정확한 중단 절차·출력 경로는 제공 런타임 안내를 따른다.

기록은 프로젝트 파일에만 남긴다. 기대값은 테스트, 하네스 승인 이유는 harness:approve, 실행 결과는 출력과 evidence,
목적·변경 이유·실제 결과·제한은 README 완성란, 계획·하네스 근거·원인 가설·받은 도움·미확인·다음 행동은 handoff.txt다.
결과 검증 활동은 업무 검사 10 + 하네스 운영 10 + review 첫 실패 10분이다.
prepare:review는 15:40에 최초 한 번만 실행한다. 그 전에는 없음/기존 존재만 확인한다.
이미 있으면 보존·사용하고 재생성하지 않는다.
수정·재검증은 review 복구 10 + 하네스 8 + 독립 전이 7 + 회귀 5분이다.
16:38–16:45 도움을 닫는다. 내용 도움은 반드시 16:45 이후이면서
첫 예측·이유·테스트와 첫 실제 결과/exit/출력을 모두 동결한 뒤에만 연다.
미실행/차단은 unknown·exit null·incomplete/HOLD로 보존한다. 실제 결과가 없으면
16:45 이후에도 환경·절차의 과정 지원만 허용하고 내용 힌트는 금지한다.
17:10–17:25의 기존 여섯 명령을 재현하고 17:25 이후에도 공개 조건을 갖춘 뒤에만 답안을 비교한다.
그 전 인계 10분은 17:00–17:04 README/handoff 4분, 17:04–17:05 저장·동결 1분,
17:05–17:07 새 비판/수동 대조 2분, 17:07–17:09 현재 파일 사람 재검토·
npm run harness:approve → npm run harness:run 2분, 17:09–17:10 npm run harness:status·근거 기록 1분이다.
approve에는 직접 검토한 이유를 붙인다. README/handoff 편집도 fingerprint를 바꾼다.
시간 절약·비판 저장은 자동 승인이 아니다. 실행 뒤 파일 변경은 재검토·새 승인·재실행 전 HOLD다.
17:10 전 갱신한 하네스 근거가 없으면 HOLD다. 이 실행 뒤에는 README/handoff를 고치지 않는다.
첫 예측/첫 결과와 전이 테스트 사본은 덮어쓰지 않는다.
여섯 명령의 결과는 출력과 evidence/v2-*.json에 남는다. 자가 채점 양식은 없고 강사가 파일을 보고 확인한다.
17:25–17:35는 조건을 갖춘 사람의 참조 비교 시간이며 17:35–17:50 강사 해설과 구분한다.
하네스 구축/운영 근거 없이는 완료가 아니다. 기술 통과는 사람의 학습 인증이 아니다.
