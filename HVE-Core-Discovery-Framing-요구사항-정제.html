요구사항 정제 09:20–10:10의 필수 본과정입니다. HVE 요구사항 정제 40분은 도입 10분 + 기존 적용 활동 25분 + 정리 5분으로 분산하고, 나머지 10분은 JavaScript·계약 시연으로 연결합니다. 프레임워크 설치·실행 없이 원칙을 수동 적용하되 기존 프로젝트의 첫 개인 테스트는 실제로 실행합니다. 본과정 440분과 그 안의 활동 265분은 그대로이며 휴식 40분·점심 60분도 유지합니다. 별도 활동 25분이나 두 번째 제출물을 더하지 않습니다.

수업의 도착점은 검토할 초안입니다. 준비된 가상 발언과 관찰을 읽어 방법을 연습합니다. 실제 인터뷰·독립적인 실증 근거·사용자 검증·조직 승인·구현 허가를 얻는 활동은 아닙니다.

공통 입력 묶음과 자료의 지위

  • 원래 요청: 앞 절의 한 문장을 그대로 남깁니다. 바뀐 문제 가설과 비교할 기준입니다.
  • 기존 공개 계약과 합성 입력: 함수 행동 계약의 처음 정책과 공개 합성 결과입니다. 수업 안에서 행동을 대조하는 기준이며 고객 필요의 증거는 아닙니다. 파일을 열거나 실행하지 않아도 아래 요약으로 진행할 수 있습니다.
  • 준비된 발언·관찰 카드: 다음 절의 작성자 제작 가상 상황입니다. 실제 참여자가 말했거나 실제 작업을 관찰한 기록이 아닙니다.
  • 제약과 미답 질문: 처음 후보는 실패만, 실행은 제외입니다. 실제 승인자·현행 흐름·업무 효과·처리량은 모릅니다.

범위를 좁히는 대화 예시

아래 대화는 작성자가 준비한 가상 카드입니다. 실제 대화 결과가 아닙니다.

질문자: “결과를 본 다음에 어떤 일을 하시나요?”

QA 역할: “다시 확인할 시험을 골라 전달하려고 해요. 어느 빌드와 모듈의 결과인지 먼저 봐야 해요.”

질문자: “우선 후보를 판단하고 전달하는 일을 살펴보겠습니다. 실제로 돌리는 허가는 누구에게 확인해야 할까요?”

고정된 수업 조건과 협의할 가설을 나눕니다. 처음 후보가 실패만이라는 것은 기존 계약의 조건입니다. QA가 어떤 표시를 원하고 어떤 전달 과정이 유용한지는 조사할 가설입니다. 요청이 구체적이라고 승인된 해결책이 되지는 않습니다. 요청의 구체성과 제약의 변경 가능성도 별개의 축입니다.

강사 노트 · 범위 대화의 의미와 이해 확인

공식 이름은 Scope Conversations입니다. 대화를 계획하고 관계자와 대화한 뒤 대상·경계·제약을 기록하는 의미를 적용합니다. 요청의 형태가 구체적인지와 제약을 변경할 수 있는지를 따로 살피는 관점도 참고합니다. 도표 완성이 목적은 아닙니다.

질문: 계약에 실패만 적혀 있으면 고객도 그것만 원한다고 말할 수 있나요? 해설: 아니요. 계약은 수업 행동의 근거이고 실제 필요는 별도 확인 대상입니다.

전환: “범위를 적었으니, 최근에 실제로 한 일을 어떻게 물어야 하는지 살펴보겠습니다.” 기존 고정 버전 출처

  • 건수와 원본 확인: 중복 대조 장면에서 출발한 임시 주제입니다. 실제 반복이 혼동의 원인인지는 추가 관찰이 필요합니다. 반복 처리 규칙 자체는 계약과 따로 대조합니다.
  • 후보 제공과 실행 허가의 구분: 상충한 권한 발언과 반대 사례를 묶습니다. 실제 권한을 정한 것이 아니라 확인해야 할 공백을 드러낸 것입니다.

행동 예시와 인수 조건

인수 조건은 “잘 정리한다” 대신 어떤 상황에서 무엇을 요청하면 어떤 결과를 확인할지 적는 것입니다. 아래는 실행 결과가 아닌 계약 기반 기대 행동입니다.

  • 동일한 실패 두 행: 위 예시처럼 한 후보와 첫 원본 근거를 남깁니다. 후보 목록을 만들 뿐 실제 시험을 돌리지 않습니다.
  • 다른 모듈의 같은 시험 번호: 별개 시험 두 개로 요약합니다. 번호만 같다는 이유로 합치지 않습니다.
  • 유효한 빈 입력: 정상 0건과 빈 후보 목록입니다. 잘못된 상태나 충돌 입력은 정상 0건으로 숨기지 않고 오류로 알립니다. 선택 밖 빌드의 오류도 먼저 검증합니다.

전체 입력의 건수와 정확한 반환 규칙은 접힌 기술 참고에 있습니다. 본문 예시는 기대 행동이지 실행 증거가 아닙니다. 요구사항 정제의 첫 개인 테스트는 아래 기존 활동에서 실제 실행하고 기대값과 비교합니다. 합성 시험의 실제 재실행이나 출시 승인은 하지 않습니다.
