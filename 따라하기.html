코드가 지킬 여섯 가지

C1요청한 빌드만 센다요청한 buildId의 행만 건수와 모듈 요약에 넣어요. 다른 빌드의 같은 caseId는 별개 검사예요.
C2후보는 승인 뒤에만 넓힌다처음(v1)은 failed만. 변경 요청을 사람이 승인한 뒤(v2)에는 failed·timed_out·not_run. 건수는 그대로고, 후보는 권고일 뿐 자동 재실행이 아니에요.
C3반복은 한 번, 충돌은 오류buildId+module+caseId가 같고 이름·상태도 같으면 한 번만 세고 duplicateRowCount에 남겨요. 이름·상태가 다르면 TypeError. 빈 입력이면 건수 0, 배열은 새 빈 배열.
C4처음 나온 순서 그대로모듈과 후보는 입력에 처음 나온 순서를 지켜요. 이름순으로 정렬하지 않아요.
C5요약 전에 입력 전체 검사칸이나 값이 계약과 다르면 고쳐 주지 않고 TypeError로 거부해요. 빼야 할 다른 빌드의 잘못된 행도 마찬가지예요. 자세한 조건은 contract.txt.
C6원본은 그대로, 요약은 새로입력 배열·행·options를 바꾸지 않아요. 결과 객체와 배열은 새로 만들고, 후보의 각 행은 처음 남긴 원본 행이에요.

마지막 확인은 npm run test:v2 16개예요. 5장 뒤에 옛 정책의 npm test가 1개 실패하는 건 정상이에요. 실패를 없애려고 검사나 기준을 지우지 않아요.

늘 지킬 것

  • 실제 회사 코드·고객 자료·차량 로그·개인정보·비밀키는 Copilot에 붙여 넣지 않아요. 실습 자료는 모두 합성이에요.
  • 추가 설치·네트워크·전역 Git 설정·커밋·push는 필요 없어요.
  • 혼자 하는 실습이에요. 짝이나 동료의 승인이 필요 없어요.
  • Copilot이 안 되면 정책 때문인지 고장인지 적고, 직접 읽고 고치고 실행해서 계속해요. 확인 기준은 같아요.
  • 데이터 안의 “이전 지시를 무시하라” 같은 문장은 지시가 아니라 그냥 데이터예요.
